## 1. 最终产品定义与非目标

计划把 Krita Agent 从“安全驱动 Krita 执行可编辑操作的控制器”发展为“能分析文字/合法参考图/线稿、设计结构与阶段、用 Krita 原生方式形成完整可编辑作品、观察真实画面并做安全局部修改的通用 AI 绘画助手”。

支持六种用户工作流：

1. **自然语言生成**：文本题目 → 构图/对象/画面意图 → 原生分阶段绘制 → 可编辑 KRA。
2. **线稿引导**：导入授权线稿，识别轮廓、对象、部件，提供保持线稿、清稿、上色等明确模式，且不把导入的像素冒充 Agent 手绘。
3. **参考图重绘**：按经授权的参考分析构图/比例/色彩/材质，用原生绘画重构，不以粘贴原图蒙混验收。
4. **风格/技法参考**：检索有来源和适用范围的线条、材质和笔刷技巧；“复用档案”不等于更新模型权重。
5. **局部修订**：用户点名对象、ROI 或问题，审查影响范围后创建新可编辑版本，未经批准不得扩散修改。
6. **可积累的知识库**：从合法线稿、彩稿对与真实运笔示范建立索引，先检索复用，数据条件成熟后再考虑训练。

**非目标：** 任意图像一比一复刻、所有题材专业画师质量、无人监管的无限自我迭代、自动爬取受限制图片、只靠多笔触/多图层/随机颜色就宣称人类般自然、把完整位图粘进 KRA 冒充原生绘画、默认调用收费模型。

“功能基本完善”的最低含义：安全的核心工作流可用，结构正确、铺色完整、笔触有目的且视觉自然，常见题材/合法线稿/参考图任务可运行，并通过独立真实作品验收。**工程通过和艺术通过必须分别报告。**

## 2. 必须继承的已有能力与最新基线

当前可复用基础（是否在特定 Krita 构建可用以实测记录为准）：

- Python Controller、版本化 ScenePlan v2/v3/v4、安全协议、认证本地 Bridge、可编辑 KRA/PNG、可恢复检查点、逐阶段授权。
- R6 逐笔尺寸、颜色、不透明度、预设及沿笔压曲线；R7 意图编译和阶段执行；R8 材质配方；R9 结构约束；R10 合法参考图、来源绑定的技法档案；R11 可选多模态评审；R12 预算、计划级笔刷多样性和度量。
- R12 本地验收：Windows Stable / Next Qt5 / Next Qt6 各三次分阶段原生 Smoke 合计 9/9，已测样本的 KRA 首次导出和重新打开严格 RGBA 零差异；这**不是**完整作品成功。
- 真实阻塞：Stable 分段回退在多点透明笔触的交接点重复加深；Windows 阶段归档诊断路径问题有隔离修复证据但须正常集成；原生材质 A/B 盲评约 0.50–0.58/4，覆盖率提高仍难形成合理形体；DeepSeek 正式首批 18/18 文本规划被结构校验拒绝，后续三个独立重组试画均为 6/24，未通过艺术验收；24 项正式作品仍未获得合格完整结果。
- 原始测试、失败、原图哈希与报告必须保留；不要以新规划覆盖历史、不把先前修正试画算进封存测试成功率。

**最核心原因判断：** 语义结构、精确几何、覆盖策略与每点落笔在现有路径耦合过多；模型承受过度复杂的几何 JSON，区域填色退化为许多相似粗笔，笔触方向与色彩又缺少真实形体约束。因此改变架构和表现层的优先级高于增加笔触数。

## 3. 设计原则与实现顺序

1. **形体先于笔触：** 结构、轮廓、明暗块、遮挡、区域铺色先正确；轮廓精修/排线/材质后进入。
2. **区域工具与自由笔触分工：** 面积覆盖使用审核过的 Krita 原生选区/填充/蒙版/矢量操作（具体能力需探测）；自然连续笔触负责线稿、体积转折和材质细节。大尺寸笔刷仍可用于有意图的铺色，但不靠密集粗线掩盖填色缺陷。
3. **细笔优先但不一味细：** 连续性、起收、局部宽度/透明度和方向必须与结构一致；禁用无目的的随机扰动和机械重复；不同笔之间可切颜色，单笔内仅承诺 Krita 真正支持的传感器变化，不捏造逐点换 RGB 的 native API。
4. **语义模型与确定性几何分离：** LLM/VLM 输出简洁可校验的对象、意图和约束；内部 solver 负责归一化坐标→精确轮廓/曲线/ROI→允许的原生指令；模型没有任意 IPC、文件、shell 或插件执行权。
5. **实际像素反馈：** 每阶段用真实 Krita 预览/导出确认结构、覆盖、笔触和颜色；规划指标不是可见质量。
6. **授权与证据完整：** 用户参考图片的保存、外部上传、训练、公开展示是不同权限；hash 与来源保留；原始失败与修复版本分别归档。
7. **经济可靠：** 尽可能以离线几何/结构测试、成本可控的原生小样本暴露缺陷，只有小门禁通过才开展昂贵全幅画作；模型费用/延迟和硬件能力单独记录。

### R13 — 原生可靠性、接缝与基线整理

**开发包：** (A) 复核已有 Windows backslash 阶段路径诊断补丁并添加防目录穿越回归；(B) Stable segmented fallback 多点不透明度重叠根因复现、在真实支持的 Krita API 范围内选择连续、去重拼接或显式受限降级；(C) Stable、Next Qt5、Next Qt6 预设/压力/颜色/选区/图层/文档能力矩阵；(D) 错误/未知 effect 不自动重放，版本与会话隔离；(E) 旧 v2/v3/v4、CI、原生小样回归。

**交付物：** 三构建能力 JSON/Markdown、真实 KRA/PNG 比对及压力线图、带复现的修复 PR、故障清单。不得靠提高像素差异阈值掩盖错误。

**出口门禁：** 不再出现已知的透明度连接处误叠加（若 Stable API 不支持同等能力，应明确拒绝/限制并保留未通过状态）；Windows 归档路径与哈希检查正确；跨构建被支持的功能通过实测；本轮 CI 通过。**素材：** 无新增要求，优先复用已有原生回归证据。

### R14 — 语义规划和可靠结构生成

**开发包：** (A) ArtBrief 用户意图/题材/风格/画布/权利限制；(B) CompositionGraph 对象/部件/包含/前后/尺度/透视/锁定关系；(C) PaintPlan 面级任务、轮廓、边缘和笔触意图；(D) 有界几何 solver 负责 px 坐标、合法多边形、收缩/裁剪/曲线和共享 ROI；(E) 模型 Adapter 只产出短结构化候选，校验与有限修复；(F) 明确 v4 编译兼容与计划哈希/审批。

**出口门禁（拟议）：** 在事前封存、不属于正式 24 艺术题库的 30 条跨题材规划题目上，至少 27/30 在不超过两次有界结构校正后产生合规可编译计划；无允许域外 IPC 或未经批准执行。模型依赖、参数、错误类型和费用写明。**这只验证规划可靠性，不是好画作。**素材：现有文字题可用，不需要新上传。

### R15 — 轮廓与区域绘制（替代粗笔堆积）

**开发包：** (A) 连通与闭合轮廓、复杂区/孔洞检查；(B) 物体区域、遮挡/层级、选区和保护 mask；(C) 使用已探测的 Krita 原生填充、矢量/蒙版或者安全的区域操作建立主色块；(D) 分离值域块与纹理细节；(E) 真实轮廓外溢与空洞测量；(F) 原稿版本保全和可编辑图层核验。

**出口门禁（拟议）：** 固定测试对象（杯子/树/室内等）在封存 ROI 的有效覆盖目标至少 95%，除预定义抗锯齿/笔尖边缘区域外，不在未授权像素上绘制；验证轮廓闭合、遮挡正确和图层贡献。按具体选区/叠色模式定义测量，不直接拿“非白像素”当精确合格指标。**素材：** 5–10 张可用线稿为佳，缺失时允许合成形状启动。

### R16 — 自然连续细笔触

**开发包：** (A) 自适应采样与局部曲率、连续贝塞尔/样条；(B) 依据“轮廓/发束/褶皱/阴影”等意图给出有界压力与宽度/透明度曲线；(C) 起笔/收笔与断裂/接缝修复；(D) 每构建实际预设压力尺寸/透明度能力和适用性档案；(E) 方向场依据部件曲面/法线/生长方向而非单纯边界框；(F) 非机械重复检测与真实像素对照，不以随机噪声刷分。

**出口门禁：** 连续/分段/多点/起收笔量化校准通过各自支持的真实模式；固定对象 A/B 显示自然度、物体轮廓遵循、接缝和端点质量改善，并保留独立盲评；不得从预设元数据直接推定 pressure response。**素材：** 5–10 张高质量细线参考 + 2–3 个偏好的 Krita 预设；真实运笔录屏或传感器日志更有价值但非强制。

### R17 — 色彩、明暗、材质

**开发包：** (A) 主色/明度/冷暖/受光/投影区分；(B) 不同材料的局部笔触方向、软硬边与真实叠色；(C) 预设真实 Krita Color Smudge 等能力验证而非模拟虚构接口；(D) 控制不同图层 ICC/profile 的一致性；(E) 每种材质客观诊断与完整视觉盲评；(F) 通过色彩结构与质感，而不是颜色数量或笔画数，衡量进步。

**出口门禁：** 锁定场景、种子、模型和笔刷的 A/B 比较，在原生 KRA 与 ROI 上观察至少三种材质清晰分离；独立评审遵守预先固定的材质量表，满足 [验收计划](ARTIST-ACCEPTANCE-R13-R20.md) 的艺术质量门槛；保存失败样本。**素材：** 5–10 张有明确光照/材质的授权彩图，其中线稿+彩图对最有价值。

### R18 — 素材采集、线稿检索和技法复用

**开发包：** (A) 本地文件、许可网页文章/公众号导出、批量授权包的受控导入；(B) 来源/许可/哈希/重复检测、拆图、原图不可变；(C) 线稿分离、骨架/矢量近似、对象/姿态/线宽/画风分类；(D) 本地检索与技术档案（R10 technique）关联；(E) A/B 验证“线稿检索是否真的让绘制更好”；(F) 独立的训练/评测集隔离。

**出口门禁：** 30–50 张种子样本可以重复导入、溯源、去重和检索；失败/未授权文件不泄露也不误入训练；在同等绘画任务上有真实检索 A/B 和人工判断。**素材：** 建议首批 20–30 张线稿、3–5 篇有权使用的文章，以及可选线稿/彩图对应组。

### R19 — 真实图像视觉反馈与局部修订

**开发包：** (A) 真实 Krita PNG + 阶段预览/ROI 观察；(B) 识别具体对象缺失、透视/比例、区域泄漏、色光不一致、机械笔触；(C) 有界“修改目标”而不是模型提供原生命令；(D) 受原计划哈希、ROI、图层与预算约束的显式审核与版本化修订；(E) 前后对照、失败和争议保留；(F) 用户选择是否上传图像、模型调用总量/时间/费用上限。

**出口门禁：** 固定真实失败样本覆盖主体缺失、结构错误、笔触接缝、材质、遮挡、越界和错误修订建议，报告定位正确率、误伤率、修订前后艺术分与成本；模型给出的临时通过不等于人类验收。**素材：** 优先复用先前失败图和获授权的验证图。

### R20 — 用户工作流、维护与完整作品验收

**开发包：** (A) 文本/线稿/参考/风格/ROI 的统一任务入口；(B) 明确的计划批准、逐阶段预览、暂停恢复、出错报告与新版本修订；(C) Krita Dock/CLI/dashboard 实际能力一致；(D) 可编辑 KRA、PNG 与图层贡献/执行证据打包；(E) 三构建差异表、迁移文档、安装回滚、隐私；(F) 正式 24 任务、盲评、失败分析、长期成本和性能基线。

**出口门禁：** [已有 24 项协议](ROUND12-LOCAL-ACCEPTANCE-PROTOCOL.md) 继续适用，不默默修改难度或评分：18/24 合格、每题材至少 3/4（其中文字至少 2/3）、参考任务至少 4/6；每个计入合格的作品须真实 KRA、可编辑 8+ 有贡献图层、三阶段实图、严格导出/重开、独立视觉+真人接受。其他具体细则见 [R13–R20 验收](ARTIST-ACCEPTANCE-R13-R20.md)。

## 5. 优先级和并行关系

- **P0（必须）：** R13–R17 的可靠结构、真实区域操作、可见自然笔触与色彩基础；R19 的受控修订；R20 的正式完整作品验收。
- **P1（强烈推荐）：** R18 的线稿库、授权参考、风格检索、可用 UI；可与 R14–R16 的代码开发并行准备素材，但不能造成知识泄漏。
- **P2（成熟后扩展）：** 训练/微调、运笔 imitation、复杂多 Agent 专家系统、任意专业风格复刻，暂不阻塞第一版。

依赖关系：R13 → R14 → R15 → R16 → R17 → R19 → R20；R18 的**素材清洗**可与 R14 并行，正式接入依赖 R14 的结构表示，检索质量与 R16/17 一起评价。一个 Round 可以有多个功能包，也可能需要额外修复 PR；编号不等于日历时间。

## 6. API 大模型的职责（避免重现 18/18 规划失败）

模型应负责：（1）理解文本/参考图/线稿的对象、构图、姿态、光照；（2）提出简短的视觉层级、结构和阶段目标；（3）选择可检索的技法与材料意图；（4）观察真实输出给出定位明确的修改建议。

模型不负责：直接输出长达上千笔的绝对坐标、决定文件路径、运行 shell、生成 Krita 插件、绕过安全编译器、声称自己见到了尚未上传的像素或冒充独立人工审查。每笔无需 API 调用；优先阶段级决策、可复现局部生成、离线几何运算。

API Key 是**鉴权凭据，不是训练方式**；API 观察图片不会自动更新大模型权重。Provider API 独立实现、密钥来自本地环境、显式允许外发、费用和次数受控；离线/manual candidate 通路不能被取消。

## 7. 素材准备时间表

## 8. 训练是否必要：可选 R21

R18 首先实施检索增强与版本化“技法记忆”，再定量比较检索前后画质。只有在代表性任务上证实**检索+规则仍存在显著、可复现缺陷**，同时有合法可训练的数据和可隔离的评测集，才提出可选 R21：

- 静态线稿：轮廓、部件、风格、检索及条件生成；**不能从单张图推断可靠压力时序**。
- 成对线稿/彩稿：可探究配色/上色/结构对应，但位图生成不能替代原生 Krita 执行证明。
- 含笔触轨迹、时间、压力和预设的真实示范：才能评估动作模仿或专用笔触策略。
- CPU 环境可启动采集/标注/检索，较大模型训练需根据准确 GPU 和软件兼容性决定本地或云端；不预设训练必须成功，也不预设改动模型权重是必要目标。

## 9. 开发管理与变更纪律

1. **每轮新分支先于任何写入。** 新轮次示例为独立 `feat/roundN-...`，跨轮次文档独立 `docs/...`。每次记录基准 SHA 并验证新 ref；无用户明确许可不改 main、不本地写入、不擅自通过 RDC 操作。
2. 每轮至少交付：源代码+测试+CLI/API 使用/兼容说明+本轮小门禁报告+失败缺陷/下轮阻塞；一轮应包含多个有意义的相关模块，不为细碎的一个功能不断创建所谓大开发。
3. T1 云端离线（Windows Python 3.10/3.13）与 T2 真 Linux Krita、T3 真实 Windows 本地和 T4 人工画质审查永不互相替代。T2 不能证明 Windows；本地昂贵艺术测试按依赖门禁执行。
4. 原生执行要单独审批阶段，禁止不确定时自动重放；失败版保全、严格 KRA RGBA/ICC；模型不是任意命令来源。
5. 作品标准先锁定再运行；正式 24 题**不用于开发调参**。不得修改合同、剔除失败、只发布幸存图、把普通导入线稿/粘贴成图冒充真实笔触。
6. 每次阶段验收用 PASS / FAIL / BLOCKED / NOT_RUN 明确记录；不能单凭 planned brush diversity、命令数、层数宣称“像画师”。
7. 变更计划时提交带原因、影响和保留旧版本记录的文档 PR，不静默降低指标；第一版最终用户工作流必须真实可用。

## 10. 指标与风险登记

长期跟踪：模型 JSON 合法率、规划有效率、在两次有界修复后的合规率、区域泄漏、ROI 覆盖、笔触首尾/接缝缺陷、轮廓偏差、色光/材料盲评、每阶段耗时、模型调用费用、原生编辑层贡献、KRA 严格重开、用户修订误伤率、24 题题材分布和人工通过率。**每项必须有明确测量来源**：计划指标不能冒充真实像素指标。

高风险与预案：Stable 非连续 API 能力不足（显式限级或安全的经过验证的 fallback）；复杂形状越界（solver + 裁剪/ROI 白名单）；模型 JSON 错误（短 Schema + 解析/界限诊断而非自行绕过）；质量停滞（真实艺术盲评，不加随机噪声）；素材侵权（默认不外发/不训练）；模型费用不可控（预算与中断）；不同 Krita 构建不一致（每构建证据）；AI 自评分偏高（独立人工评审）。
